ai-log pipeline

Every machine copies its Claude Code and Codex sessions into one Dropbox folder, once a day. Each session is saved twice: a small skeleton for reading and mining, and a full archive that keeps almost everything. github-month-review reads from here to see the work GitHub doesn't show.

Measured on 20 October 2026: about 12 GB of session logs on two machines became 958 MB.

How a run works

ailog.py runs on each machine against that machine's own logs. It needs nothing beyond macOS's built-in Python. The full archive also needs zstd, ImageMagick and ffmpeg; without them, only the skeletons are written.

Claude and Codex sessions stay in separate folders, claude/ and codex/, under each machine. Their records keep each app's own format. Each line in an image index also names its app, so pooled image lines still say where they came from.

The index puts both apps into one shape. A day's hands-on hours count every prompt you typed, in either app, on any machine. In September, Codex added 32 hours to the 118 already counted from Claude on this Mac.

Each run

ailog.py

  1. Find every session file.
  2. Skip any whose size and modified time match the last run.
  3. Write a skeleton and a full archive for each one that changed.
  4. Never delete. A session that ages out of ~/.claude after 365 days stays here.

When it runs

Daily at 9 a.m. through launchd. Since June, 9 a.m. has been one of your quietest hours, with 19 prompts. A run missed while the Mac slept happens when it wakes. A lock stops two runs from overlapping.

How it's compressed

Images are 10.3 GB of the 11.6 GB on this Mac, stored inside the logs as base64 text. Removing duplicates leaves 3.9 GB in about 14,500 images. Each kind of content gets its own treatment.

Session textzstd at level 19 with a 128 MB window. Lossless; read back with zstd -dc.—about 10× smaller
Any imageStored once, named by a hash of its content. The same screenshot in ten sessions, or on both machines, is kept once.10.3 GB3.9 GB

Known cost

A session whose file has changed is recompressed from scratch, not appended to. Finished sessions are written once and skipped after that. Only a session that is still open, or one you resumed, is redone. Images already stored are skipped. A subagent's video is re-encoded only if that subagent changed. The first run over everything took 6 hours. The next run, 3 hours later, redid 9 sessions in 51 seconds. That included a 241 MB session that was still open.
